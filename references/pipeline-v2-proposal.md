## 两阶段交付为什么这么设计

- 超分是最贵的一步（8K tiled ≈10-15 分钟/张），给注定被删的废片烧显卡纯浪费
- 「删没删」= 天然幸存判定，零状态管理
- 正好嵌进用户的拍板节奏（他要求「我拍板一步你做一步」）
- 代价：两阶段之间用户不在场时流程停住等他，整批总时长跨两次排期

## 两个「难点」的解法（用户原话：批量生图全部图上传、一张一张不间断）

**答案：串行不靠脚本循环盯，靠 ComfyUI 队列原生能力。**

1. **全传** —— for 循环 POST `/upload/image`，整夹秒级传完
2. **全入队** —— 每张图构造独立 workflow，连续 POST `/prompt`，N 张 = 队列 N 个任务
3. **服务器串行** —— ComfyUI 队列天生逐个执行、零间隙衔接；单张失败自动跳过不炸批
4. **队尾对账** —— 脚本只轮询各 `prompt_id` 的 `/history`，全 success 后统一落盘报清单

比「提交→盯完→再提交」强在：真不间断 / 抗崩（脚本挂了队列照跑，重启后从 history 补落盘）/ 断点续跑免费。
可跑代码见本 skill `scripts/qwen21_batch_queue.py`。
